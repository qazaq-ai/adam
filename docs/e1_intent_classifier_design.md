# E1 — Discriminative Intent Classifier

**Status.** Design draft. Branch `experimental/e1-intent-classifier`,
forked from `experimental/agglutinative-neural` at commit `08dfaf9`
on 2026-05-21.

**Hypothesis under test.** A small (~10K – 1M parameters)
discriminative model trained on FST-synthesised + unit-test
labelled Kazakh phrases can replace the hand-written
`detect_intent` / `detect_*` cascade (currently 60+ functions
spread across `semantics.rs` and `discourse.rs`) at **equal or
better accuracy**, **comparable or better latency**, and
**zero hallucination by construction** (closed-set output).

If the hypothesis holds, E1 becomes the first proof point for the
project's broader research thesis: **neural is not synonymous with
LLM**. Discriminative classification over a closed label set is a
fundamentally different beast from generative free-form text, and
the safety / cost / predictability properties of the former
survive the use of learned parameters.

## Scope

**In scope.**

- A single neural artefact that, given a Kazakh utterance, returns
  one of ~80 known intent labels (the closed enum surveyed in
  `intent.rs` + the dispatch tree inside `interpret_text_with_lexicon`).
- A training pipeline producing the artefact from
  - existing `detect_*` functions used as labelling oracle, AND
  - FST-synthesised paraphrases generated by `adam-agg-synth`.
- An evaluation harness comparing the model against the current
  hand-written cascade on a held-out test set.
- A production-gated integration point in `Conversation::turn` so
  the new classifier is reachable behind `ADAM_NEURAL_INTENT=1`
  while the default path stays deterministic.

**Out of scope (for now).**

- Slot extraction (NER) — covered by a future experiment **E2**.
- Topic salience ranking — covered by future **E3**.
- Anything involving free-form text generation. The deterministic
  template renderer keeps producing all surface answers.

## Why this is the right first experiment

1. **Surface where structural debt is highest.** The
   `detect_*` cascade is the single piece of the kernel that grows
   linearly with every Codex audit. Each audit adds 1–3 new
   detector branches; the cumulative file size of `semantics.rs`
   is now ~3700 lines, and each detector has its own subtle
   precedence interaction. A learned classifier collapses this to
   one artefact whose behaviour is studied as a whole.

2. **Closed output space.** Output is one of ~80 intent labels.
   The model literally cannot emit anything else — hallucination
   is impossible by construction, not by post-hoc filtering.

3. **Cheap evaluation.** The current cascade is itself an oracle
   on the inputs it already handles correctly. We can label
   thousands of examples automatically by running the cascade and
   storing its answers (with a 20 % held-out set for honest test
   accuracy).

4. **Trivial fallback.** If the model is uncertain or disagrees
   with a high-confidence pattern, fall back to the cascade.
   Worst case, we get the current behaviour; best case, we get
   the cascade's generalisation closure.

## Architectural ladder

Start with the simplest model that passes the success criteria
below; promote one rung up only if it doesn't.

### Rung A — Linear classifier over hash-features

- Input: hashed character n-grams (3..5) + token unigrams + a
  small set of hand-rolled binary features (has-question-mark,
  contains-digit, starts-with-imperative-verb, …).
- Output: scores per intent, argmax.
- Parameters: ~10K (one weight per feature × |intents|).
- Implementation: pure Rust, zero new deps. Forward pass is a
  single sparse dot product.
- Why first: 100 % transparent (you can print which features
  fired and how much each contributed), trains in seconds on
  laptop CPU, fits comfortably in 100 KB.

### Rung B — Tiny embedding + linear

- Input: averaged 16-dim embedding over tokens (vocab from FST
  roots + frequent suffix surfaces).
- Output: linear projection to intent logits.
- Parameters: ~500K (vocab_size × 16 + 16 × |intents|).
- Why second: handles paraphrases the linear model misses;
  embedding is still interpretable (you can list the top-k
  neighbours of every vocabulary item).

### Rung C — Two-layer feedforward with attention

- Input: 32-dim embedding + 1-head self-attention + linear head.
- Output: intent logits.
- Parameters: ~1M.
- Why third: only if Rung B fails to hit accuracy on
  long-range / compositional intents (e.g. multi-clause
  IntroProposal).

The discipline: **don't promote** unless the previous rung fails
a binary criterion. Each rung adds parameters but also adds
opacity. The goal is the smallest rung that works.

## Training data

### Sources

1. **Cascade oracle.** Run the current `detect_*` cascade against
   every input in our corpora:
   - `data/eval/*.json` (1500+ holdout cases)
   - `data/eval/factual_eval_100.json`
   - `data/eval/adversarial_dialog_v1.json` (95 cases)
   - `tests/end_to_end.rs` extracted phrase literals
   - `data/eval/live_holdout*.json` series

   For each `(input, intent)` pair the cascade emits, store it as
   a labelled training example. **Confidence policy:** keep only
   labels the cascade attaches `noun_hint_confidence: High` to,
   OR labels that match a class with no confidence axis (greetings,
   safety refusals, math). Skip Low-confidence Unknown — we
   don't want to teach the classifier "Unknown" as a positive
   class.

2. **FST-synthesised paraphrases.** For each intent class with
   fewer than 100 cascade-labelled examples, generate variation
   via `adam-agg-synth`:
   - Different morphological paradigms on the head verb
     (1sg/2sg-informal/2sg-polite/3sg + tense variants).
   - Different word orders (Kazakh is moderately free-order; SOV
     is canonical but OSV and OVS occur in real speech).
   - Phonetic surface variants (the same set the v6.0.5 normaliser
     handles in voice mode — köbeit/köbeyt/kobet etc.).

3. **Negative-class injection.** For each positive intent class,
   sample 10 % random phrases labelled with **different** intents.
   This is the discriminative analogue of dropout — forces the
   model to learn cross-class boundaries, not just per-class
   templates.

### Schema

`data/intent_classifier/v1/dataset.jsonl`:

```jsonl
{"id": "ds_00001", "input": "Сәлем, қалайсыз?", "intent": "AskHowAreYou", "source": "cascade", "confidence": "high"}
{"id": "ds_00002", "input": "Менің атым Дәулет", "intent": "StatementOfName", "source": "cascade", "confidence": "high"}
{"id": "ds_00003", "input": "Кеше кешке үйде болдым", "intent": "StatementOfLocation", "source": "fst_synth", "confidence": "high"}
```

Split: 80 % train / 10 % dev / 10 % test, stratified by intent
label. Test set is **frozen** at generation time and never seen
during training — even hyperparameter selection happens on dev.

### Target size

- Minimum: 5000 labelled pairs across ~80 intents (~60 per class
  median).
- Aspirational: 20 000 pairs with at least 100 per class.

## Evaluation

### Success criteria (binary, must hit all)

1. **Accuracy ≥ 99 %** on the frozen test set. Below this we
   either retry with the next rung or abort the experiment.
2. **Latency p99 ≤ 5 ms** per inference on M2 CPU (single
   thread). Above this and the classifier is slower than the
   cascade — there is no point.
3. **Model size ≤ 5 MB** on disk. Above this and we are no
   longer "small".
4. **Zero hallucination.** Output domain is exactly the closed
   intent enum; nothing else can come out.

### Comparison metrics

For every test-set input, run:
- The deterministic cascade (existing behaviour).
- The neural classifier.

Report a 2×2 contingency:
- Cascade right + neural right → **double win** (good)
- Cascade right + neural wrong → **neural regression** (bad — count these)
- Cascade wrong + neural right → **neural improvement** (good)
- Both wrong → **shared blind spot** (instructive)

The promotion criterion is **net positive after subtracting
regressions** AND **no regression on safety classes** (medical,
legal, financial, self-harm).

### Trace artefact

For every test-set input the harness emits an audit row:

```jsonl
{"input": "...", "cascade": "AskHowAreYou", "neural": "AskHowAreYou", "neural_top3": [["AskHowAreYou", 0.97], ["Greeting", 0.02], ["AskName", 0.01]], "agree": true}
```

Persistent in `data/intent_classifier/v1/eval/`, indexed by
training run timestamp.

## Production wiring

### Gate

`ADAM_NEURAL_INTENT={1|0}` environment variable, default off. When
on:
1. The classifier runs first.
2. If `top_score - second_score < 0.15` (uncertainty band),
   **fall back** to the cascade and log a disagreement row.
3. If the classifier's prediction is in a safety class
   (medical / legal / financial / self-harm) AND the cascade
   *also* fires a safety pattern, **trust the cascade**. Safety
   conservatism: a deterministic pattern match is the more
   trustworthy signal in high-stakes domains.
4. Otherwise use the classifier output.

### Logging

Every disagreement between cascade and classifier is appended to
a session log at `data/intent_classifier/disagreements.jsonl`.
This is the next iteration's labelled-improvement queue.

### Rollback

`ADAM_NEURAL_INTENT=0` (default) entirely bypasses the new code
path. No risk of regression in the default invocation.

## Implementation plan (first sprint)

1. **Branch + design doc** ✓ (this document)
2. **Crate stub** — `crates/adam-intent-classifier/` with the
   public `classify()` signature, empty implementation, types
   for the loaded model artefact, error types.
3. **Dataset generator** — `tools/intent_dataset/` binary that
   walks the eval corpora, runs the existing cascade, and emits
   `data/intent_classifier/v1/dataset.jsonl`.
4. **Baseline harness** — measures the cascade's own latency and
   accuracy distribution across intent classes on the test split.
   We need this baseline before we can claim anything about the
   classifier.
5. **Rung A trainer** — pure-Rust linear classifier over hash
   features. Loss = cross-entropy. Optimiser = AdaGrad on sparse
   features. Training loop: 30 epochs, eval on dev each epoch,
   early stopping on dev plateau.
6. **Rung A evaluator** — runs the trained model against the
   frozen test set, emits the agree/disagree contingency, prints
   the 2×2 table + per-class precision/recall.
7. **Rung A integration** — `Conversation::turn` gated branch.
8. **Stop-or-go decision** — meet success criteria on Rung A?
   Ship; otherwise promote to Rung B.

## Open questions deferred to first sprint

- **How sparse is the natural feature space?** The hash trick
  works best when feature density is moderate. If unigram +
  trigram + binary signals are too sparse, dev accuracy will
  plateau early and we will need embedding.
- **What's the right vocab unit for embedding?** Token-level
  vocab is large in Kazakh because of agglutinative case marking.
  Morpheme-level (FST-segmented) vocab is smaller but requires the
  FST to run before the classifier, which doubles latency.
  Probably the right answer is **root-level** vocab (~16k
  entries) — the FST already gives us roots cheaply.
- **How many positive classes are actually distinguishable?**
  Some intents are extremely close (Compliment vs. WellWishes
  vs. Thanks). We may collapse them at training time and
  re-distinguish at slot-extraction time.

## Anti-success: what would invalidate the experiment

The experiment is honest only if we predeclare what makes it a
failure:

1. **Rung A accuracy below 95 % on dev.** Hash features are
   insufficient for Kazakh agglutination.
2. **Rung B accuracy below 99 % on test.** Discriminative
   bottleneck for our intent space is structurally hard. We may
   need slot-aware multi-task learning, or the cascade may have
   already captured everything cheaply learnable.
3. **Net regressions on safety classes after promotion.** Hard
   stop. The deterministic cascade ships.
4. **Latency > 5 ms even on Rung A.** Hash classification is
   essentially free; if we miss this budget the implementation
   has a bug we should fix, not a research signal.

In any of these cases we write up the negative result, archive
the artefacts, and **return to the deterministic cascade
unchanged**. That is also a research outcome — knowing that
discriminative ML doesn't help here is useful information for the
research thesis.
